# 임팩트기업 사업기획

## 목적과 기준

기업이 무엇을 누구에게 제공하고, 어떻게 지속 가능한 수익과 사회·환경적 변화를 만드는지 설명하고 개선한다. 특정 기업·산업·사업모델·페이지 수를 기본값으로 삼지 않는다. 공식 제출 양식과 사용자의 목표·범위를 우선한다.

- 수혜자, 사용자, 결제자와 구매 결정권자를 구분한다. 같은 주체일 수도 있다.
- 제품·서비스의 제공 방식, 고객의 구매 이유, 수익 구조와 임팩트의 발생 경로를 연결한다.
- 확인 사실·계산·가정·목표·미확인을 구분한다. 출처·기준일·단위를 보존하며 없는 인터뷰·계약·매출·성과를 만들지 않는다.
- 사업 성장과 임팩트 확대의 연결, 충돌 가능성과 실행 제약을 함께 본다. 활동량만으로 수혜자의 변화를 입증하지 않는다.
- 인증·지정 상태는 제공된 증빙 범위에서 다룬다. 자격·지원요건을 판단할 때는 해당 시점의 공식 자료를 확인한다.

## 시작과 자료 선택

먼저 목적, 독자, 사업 단계, 기준일, 현재 자료와 요청 범위를 파악한다. 기존 자료에서 확인한 내용을 활용하고 결과를 바꾸는 누락만 질문한다. 자료가 적어도 확인 가능한 부분부터 진행하고 미확인 항목을 표시한다.

기존 기업정보 파일이 있으면 먼저 읽고 재사용한다. 파일이 없을 때만 아래 양식의 필요한 부분을 기업 작업 폴더에 복사해 작성한다. 스킬 원본에는 기업 자료를 저장하지 않는다.

### 파일 재사용과 갱신

- 기업정보는 반복 사용하는 자료이며 영구히 고정된 정보가 아니다. 회사 폴더의 기업정보·사업가정·의사결정과 해당 작업에 필요한 근거를 읽고, 실제 파일 경로·기준일·승인 상태를 확인한다. 프로젝트에서 정한 경로를 따르며 특정 폴더명을 필수 조건으로 삼지 않는다.
- 프롬프트에는 이번 작업·추가 조건·참조 파일·산출물과 확인 기준을 둔다. 저장된 기업정보 본문이나 스킬 전체를 매 단계에 다시 붙이거나 웹 재입력을 요구하지 않는다.
- 조사·계산 결과를 기획에, 승인된 기획을 IR에, 검토 기록을 수정 작업에 연결한다. 기존 산출물이 있으면 필요한 범위에서 재사용하고, 근거가 바뀐 부분과 영향받는 표·본문·숫자를 갱신한다.
- 필수 파일이 없거나 읽을 수 없으면 위치·필요 정보를 확인한다. 읽지 않은 자료를 확인했다고 말하거나 예시·대화 기억으로 대체하지 않는다. 독립적으로 진행 가능한 작업은 미확인 범위를 표시하고 계속한다.
- 여러 버전이 충돌하면 파일명이나 수정시각만으로 확정하지 않는다. 사용자가 지정한 버전·기준일·승인 기록을 대조하고 해결되지 않는 차이는 질문한다. 최초 워크북 원문은 기록으로 보존하며 현재 자료 위에 덮어쓰지 않는다.
- 새 제안은 가정·검토 기록에 둔다. 고객·가격·예산·미션 등 사업 조건은 대표 채택 후 기업정보에 결정일·근거와 함께 반영한다. 읽기 전용 검토 역할은 변경안을 반환하고, 편집 권한을 가진 역할이 승인 범위에서 저장한다.

## 기획과 개선 흐름

1. **논리 정리** — 고객 문제·기존 대안·제공 가치·수익 구조와 사회문제·수혜자·활동·변화·측정 방법을 연결한다. 실제 자료와 가설을 구분한다.
2. **초안 작성** — 독자의 질문 → 핵심 답 → 실제 본문·근거 → 시각화 순서로 구성한다. 표제는 짧고 구체적으로 쓰되 문체를 고정하지 않는다. 기존의 유효한 내용과 중요한 조건을 보존한다.
3. **관점별 검토** — 검토 기준을 읽고 전달력·사업성·임팩트·투자자 적합성을 구분해 평가한다. IR은 투자자 관점 검토를 기본 포함한다. 다른 목적에서도 검토를 요청하면 적용하되 공식 평가항목을 대체하지 않는다.
4. **개선안 선택** — 판단을 막는 이유를 특정하고 영향·선행조건·비용·시간으로 우선순위를 정한다. 회사의 목표·자원·미션에 맞춰 채택·보류·제외를 제안한다. 타깃·가격·예산 등 중요한 사업 결정은 대안과 이유를 제시해 사용자 판단으로 남긴다.
5. **수정과 복귀** — 표현은 원고로, 근거 부족은 조사로, 수치 오류는 계산으로, 사업 구조는 논리 정리로 돌아간다. 전체 보완 범위에서 가능한 조사·계산·로컬 수정은 실행한다. 실제 고객 행동이 필요한 문제는 검증 과제로 남긴다.
6. **재검토** — 실제 변경·새 근거와 연결된 항목을 다시 평가한다. 반박 결과도 보존하고 관련 본문·표·숫자를 함께 갱신한다. 문장 개선을 사업성과나 실증 성공으로 바꾸지 않는다.

새 근거·분석·의미 있는 수정이 없으면 같은 평가를 반복하지 않는다. 내부 보완을 마친 뒤 남은 항목을 외부 검증 대기·사용자 결정 필요로 구분한다. 외부 결과를 기다리는 동안 독립적인 내부 보완은 계속한다. 고객 연락·결제·계약·외부 제출은 별도 요청 범위를 따른다.

## 결과 전달

요청한 구성·원고·수정본을 먼저 제공하고 핵심 개선 사항, 남은 보류 사유와 다음 행동을 덧붙인다. 재검토는 달라진 판단과 근거를 함께 보여준다. 내부 검토 기록은 외부 발표 본문에 넣지 않는다.

최종적으로 사업과 임팩트의 연결, 주장과 근거의 일치, 기존 내용 보존, 목적·분량 충족을 점검한다. 완성 파일을 요청하면 해당 환경의 제작 도구로 만들고 확인한다. 다른 개인 스킬·계정·특정 경로는 필수 의존성이 아니다. 조사 도구가 없으면 확인 한계와 필요한 자료를 명시한다.
